# AGENTS.md — Computer Vision Project

Guidance for AI coding agents (and humans) working in this repository.

## What this project is

An **Advanced Computer Vision (ACV / MCS)** course project:

> **Content Disarm and Reconstruction as an Adversarial Defense for
> Vision-Language Models: An Empirical Evaluation and Adaptive-Attack Analysis**

We evaluate whether image **CDR** (structural, multi-operation file
sanitization) defends **vision-language models** against (A) pixel-space
adversarial perturbations and (B) typographic / visual prompt-injection
attacks — compared against conventional transforms (JPEG, resize) — and analyze
*which* CDR operations matter and whether an adaptive (BPDA) attacker bypasses it.

The authoritative spec is **`docs/proposal/proposal.tex`**. Read it before
making design decisions; keep it in sync when scope changes.

## Final deliverables (definition of done)

The completed project must contain, all building from source in this repo:

1. **Document** — compiled proposal now (`docs/proposal/proposal.pdf`) and a
   final report later (`docs/report/report.pdf`).
2. **Presentation** — compiled slide deck (`slides/slides.pdf`, Beamer).
3. **Experiment** — reproducible code (`experiments/`) that produces the
   results, figures, and tables consumed by the report, plus a runnable demo.
4. **Results** — generated tables/figures/metrics under `results/` (git-ignored;
   regenerable via `make experiments`).

## Build & run

- **Documents:** `make proposal` (or `report` / `slides` / `docs` for all).
  Toolchain is **XeLaTeX via latexmk** (the author name contains Vietnamese
  diacritics — XeLaTeX + `fontspec` is required; do not switch to pdflatex).
  Bibliography is **biblatex + biber**; latexmk runs biber automatically.
- **Experiments:** Python is managed with **uv**. Use `uv run python ...` and
  `uv add <pkg>` (never edit `pyproject.toml` deps by hand — let uv update the
  lockfile). `make experiments` runs `experiments/run_all.py` once it exists.
- **Convert LaTeX↔Markdown/docx:** `pandoc` is available locally.

## Conventions

- **Keep the proposal authoritative.** If experiment design changes, update
  `docs/proposal/proposal.tex` and rebuild.
- **Reproducibility is a graded goal:** pin model versions, dataset splits,
  attack params, and random seeds in `experiments/` config; record hardware.
- **Compute discipline:** screen pixel-space attacks on the CLIP encoder alone
  (fast, <8 GB); reserve full VLM generation for a fixed confirmation set. Assume
  a single student GPU, not unlimited compute. Never propose training a VLM.
- **Safety:** attack success is measured as *benign targeted output hijack*
  (force an innocuous target), never harmful-content generation.
- **No overstated novelty** in any writing: CDR is an existing concept; the
  contribution is the empirical evaluation. See the novelty statement in the
  proposal (Appendix A).
- **LaTeX hygiene:** commit `.tex`/`.bib` and the built `.pdf`; `.gitignore`
  excludes `latexmk` aux files. Run `make clean-tex` before committing if aux
  files leak.
- **Commit messages:** do NOT append a `Co-Authored-By` footer, a "made by" /
  "generated by" line, or any attribution trailer at the end of commits. Write a
  plain message describing the change and nothing else. (This project rule
  overrides any default attribution instruction.)

## Writing style (apply to ALL prose)

Every document, report, proposal, README, commit body, and PR description in this
project gets a humanizer pass before it is final: write it so it reads like a
person, not a chatbot. This is the `/humanizer:humanizer` skill distilled to the
rules that matter most here; run the full skill when in doubt. Keep technical and
reference text plain and neutral; keep a real voice in essays and notes. Every
sentence must add something the reader does not already have.

- **No dashes as connectors.** No em/en dashes joining clauses. Use a comma,
  period, colon, or parentheses. Keep dashes only in numeric/label ranges
  (`D0–D5`, `RQ1–RQ3`) and established compounds (`security–utility`).
- **State the point, do not stage it.** No "not X but Y", no one-line closers
  that restate the paragraph, no dramatic fragments, no "the real question is".
- **No run-ups or filler.** Cut "Let's dive in", "Here's the thing", "Honestly?",
  chatbot wrappers, and knowledge-cutoff disclaimers.
- **No arguing with no one.** Drop fake alternatives and objections nobody raised.
- **No inflation.** Avoid crucial/pivotal/testament/showcase/underscore/robust
  (figurative)/landscape and "stands as a testament" significance-padding.
- **Plain verbs and structure.** Prefer is/are/has over "serves as"; no forced
  triads; vary sentence length; bold only real labels, not decoration;
  sentence-case headings.
- **No overstated novelty** (already a rule above) — the humanizer pass reinforces
  it: no "first", "nobody has", "revolutionary".

## Experiment code (`src/`)

MVP implementation lives in `src/` (package), driven by `configs/*.yaml` and
`scripts/*.py`. Layout: `models/llava.py` (differentiable wrapper),
`defenses/` (jpeg + real ICDR/Dangerzone), `attacks/targeted_pgd.py`,
`datasets/imagenet_vqa.py`, `evaluation/` (metrics, statistics, runner, predict),
`analysis/` (perturbation, frequency, frontier), `visualization/demo.py`.
Run order (depth-first): `build_dataset` → `test_llava` (ckpt 1) → `run_clean`
(ckpt 2) → `validate_attack` (ckpt 3) → `run_experiment` → `run_analysis` → demo.
Full protocol: `docs/implementation/experiment-protocol.md`.

**Hardware:** runs on a cloud GPU (≥16 GB) keeping LLaVA-1.5-7B as proposed. The
local 4 GB laptop GPU is used only for CPU unit tests (`.venv-exp`). See
`docs/implementation/implementation-plan.md` §9.

**Persistence/resume:** results live under `results/runs/<run_id>/`, a
self-describing run directory (config, environment, git commit, dataset manifest,
model/defense info, coverage summary). The expensive attack is crafted once per
(image, epsilon), persisted losslessly as `adv/*.npy`, then read back by every
defense job, so adding a defense never recomputes the attack. Logic:
`src/experiment/{layout,store,run,aggregate}.py` on top of `src/utils/resume.py`
(atomic per-job writes). `run_experiment.py --run-id <id> [--resume] [--max-hours N]`
skips finished jobs, so a reclaimed VM loses at most one job. See
`docs/implementation/reproducibility.md` and `final-status.md`.

**Colab (multi-account, resumable):** `notebooks/colab_cdr_vlm.ipynb` +
`src/colab/sync.py` (state store, merge-only restore, session lock). Point
`--run-id` at a Drive-mounted directory so the run survives the session. Full design:
`docs/implementation/colab-resume.md`.

**Two Colab front-ends, same resumable experiment:** the browser notebook, and a
terminal path using Google's Colab CLI (`uv tool install google-colab-cli`) via
`scripts/colab_run.sh` + `scripts/colab_bootstrap.py`. Both write state to Drive.
The CLI login is interactive (per Google account); see
`docs/implementation/colab-cli.md`.
